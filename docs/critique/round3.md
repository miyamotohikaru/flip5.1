## 定点 `noon` / `cloudy` の移動について（判定つき）

**判定: 記録された理由は事実として正しい。検証もできた。ただし変更としては「半分だけ妥当」で、この一手は作品を良くしていない。**

事実確認（こちらで独立に測った）:

- 旧 noon（`pos=60,386.13 look=-35,-2`, 12.2 時）を今日の版で撮り直した（`shots/r3x_noon_old.png`）。
  太陽の水平方位は −3°、カメラ前方は 145°、その差 148°＝**太陽はカメラの真後ろから 32°**。落ち影は今日でも 1 本も見えない。
  「構図のせいで影が見えない」という報告は**正しい**（報告の 23° と実測の 32° の差は測り方の違いで、結論は変わらない）。
- 旧 cloudy（`pos=220,536.13 look=-60,6`, 14.5 時）も同様（`shots/r3x_cloudy_old.png`）。曇りの拡散光なのでそもそも影は出ない。
- 「影の仕組みは変えていない」も裏付けが取れた。`renderer.shadowMap.enabled=false` との差分画像で、
  **cloudy は 21.4% の画素が 10/255 以上変わる**（前景の土に木の影の形がはっきり乗る）。影は実在し、機能している。

その上で、批評側としては次のように見る。

1. **「影が無い」は R2 の 2 番目の指摘だった。その指摘のラウンドで、批評の物差しである定点を、影が出る向きへ動かした。**
   理由が正しくても、これは利益相反である。`docs/CRITIC.md` の文言（「写真として成立していないときだけ動かす」）は満たすが、精神は満たしていない。
2. **新しい 2 点は、写真として旧 2 点より悪い。** 旧 noon は湖・山脈・草原の三段の風景、新 noon は緑の斜面に段ボールの木が数本。
   旧 cloudy は雲と山脈の広い風景、新 cloudy は裸の土の斜面。実際、点は上がっていない（noon 4→4、cloudy 5→**4**）。
   点を取りに行った変更なら失敗しているし、良い画を求めた変更なら判断を誤っている。
3. **推奨: 旧 2 点を `noon` / `cloudy` に戻し、新しい 2 点は `noon_side` / `cloudy_side` として 13・14 番目に足す。**
   物差しの連続性（R1→R2→R3 の比較可能性）は批評の価値そのもので、捨てる理由が無い。
   影を見せたいなら**足せばよく、置き換える必要は無かった**。

### 黒板（入口） — **7 / 10**

良い（正確に認める）:

- **手書きの線文字が本物。** チョークの粉、筆圧の変化、字ごとのゆらぎ、下線の走り書きまである。
  「手書きフォントのファイルを置かない」という縛りを守ってこの品質は素直に凄い。
- **失敗した式が打ち消し線＋消し跡で残っている。** `h = 700·Σ2⁻ⁱ·n(2ⁱ·0.0008·xz)` / `σᴹ(h)=3.2·10⁻³·e^(−h/2.5km)` /
  `σᴹ(h)=1.0·10⁻²…+haze(h)` / `c=(a·b)^2.5·(0.6+0.4c′)·3` / `w_leaf=0.034m, c_tip=(0.30,0.42,0.115)` /
  `#define PI | const float PI` の 6 本。
- **失敗の中身が R1・R2 の批評そのもの**（「ミーが弱く、夕焼けが白いままだった」「葉幅 3.4cm の萌黄 →『麦畑』」
  「空と水で PI を二度宣言。シェーダが無言で死んだ」）。**思考量と試行錯誤は完全に伝わる。ここは設計意図どおり成功している。**
- 出典が file:line で入っている（`src/engine/core/height.ts:211 heightAt(x, z)` / `src/engine/audio/birds.ts:148`）。嘘が無い。

減点:

1. **打ち消された式と注記のコントラストが低すぎて、原寸で読めない。** 実際の黒板は消した跡が「明るく」残る（今は暗い）。
2. **注記・章名・出典が UI のサンセリフ／等幅で、チョークと混ざっている。** 「全部数式で描く」という芯が、文字の半分で破れている。
3. **板に見えない。** 額縁・チョーク受け・粉のたまり・拭き跡の横筋が無く、「暗い背景＋チョークの文字」。
4. タイトルカード（数式の絶景＋本文 4 行＋入るボタン）が板の上に重なる。**携帯では「空 SKY」「水 WATER」の章の上に完全に重なり、両方読めない。**
5. `?bb=hold&bbfont=1` の線文字見本が壊れている。`ABCDEFGHIJKLM` のあと改行して `NC` で終わり、
   数字・小文字・ギリシャ文字・記号が無い。加えて前の節の見出し「TERRAIN」が消えずに「線文字の見本」と重なる。

### 世界の隅「いま計算していること」 — **6 / 10**

- `h( 0, −555) = 51.1 + 0.0 + 0.42 = 51.50 m` が黒板の `h(x,z) = base + mtn + fine` と一対一で対応している。**因果は成立している。**
- 照準の点（画面中央のドット）で「どこを測っているか」が分かるのも良い。
- 減点: 文字が暗すぎ、出典行は原寸で読めない。桁揃えの空白が `printf` のデバッグ出力に見える。
  中央下の操作ヒントと同じ行に並んで競合する。`mtn = 0.0` が「山の式なのに 0」で、初見の人には伝わらない。

### 実験室 — **7 / 10**

- 7 本のつまみそれぞれに、日本語ラベル＋実際の式＋動かす項のハイライト＋現在値（単位つき）＋出典（file:function）。**契約は完璧。**
  （山脈の高さ／尾根の鋭さ／侵食の強さ／ミー散乱／レイリー散乱／オゾン層／雲量）
- 見出しの「数式のここを動かすと、目の前がこう変わる。」が、この作品で言うべきことをそのまま言っている。
- 減点: **変化が見えない。** before/after も、動かしたときにどこが変わるかの手がかりも無い。
  **全部「×1.00」なのにハンドル位置がばらばら**（山脈 38% / 尾根 62% / 侵食 50% / ミー 28%）で、バグに見える。
  7×4 行の文字の壁で、一般の人は式を読む前に閉じる。最初の 1 本だけ大きく出して残りを畳むべき。

### シード — **5 / 10**

- `seed=7` `12345` `314159` の 3 つとも**破綻ゼロ**。湖・山脈・草原・木の分布がすべて成立し、どれも写真として撮れる。堅牢性は合格。
- 減点: **4 枚がほとんど同じ絵になる。** 湖が同じ位置・同じ幅、山の高さの階級も木の分布も色も同じで、
  変わるのは山のシルエットだけ。「たったひとつの種から全部出ている」という圧縮の凄さは、**違いが見えて初めて効く**。
  今の見せ方は、むしろ「どの種でも同じ景色しか出ない」という逆の印象を与える。
  地形の主振幅・湖の半径・気候（樹種と草の色）・岩の露出率をシードで ±60% 振り、
  入口で 3 枚のサムネイルを並べて「同じ式・違う種」と書くべき。

### 携帯の裏返し — **3 / 10**

- **数式パネルは背景を隠す。** 画面の内訳は上から HUD（題名＋ボタン 4＋天気 5＋時刻スライダ）で 20%、
  「地形 TERRAIN」パネルで 23%、世界の中の「湖 LAKE」の箱で 12% ＝ **画面の 55% が文字**。
  裏返した世界が見えるのは細い帯だけで、いちばん見せたいものが見えない。
- パネルの中身が `base = 51.1 湖底+土手+丘` / `mtn = 0.0 尾根 ridged₅` / `sd = |xz| − r_shore = 264 m` と開発コンソールそのもの。
- 直し方: 携帯では 1 行の要約（`h = 51.5 m ＝ 51.1 + 0.0 + 0.4`）だけ出し、タップで展開。
  世界の中のラベルは同時に 1 個まで。HUD は裏返し中に畳む。

## 批評側の注記

- **前回より確実に良くなったところ**（過小評価しないために明記する）:
  雨の湖面の市松ノイズ・インポスターの矩形・葉のディザ・地形のタイル継ぎ目・水面下の草・黒潰れ・夜の「青い昼」・
  黄昏の空の色・裏返しの波の縁。**これは 9 項目で、R2 の指摘のうち「壊れているもの」はほぼ全部潰れた。**
  とくに雨の湖面と、旧 cloudy 位置で矩形が完全に消えていたことは、並置して確認した確かな成果。
- **黒板は、この作品でいちばん強い新要素。** 失敗した式が消し跡つきで並び、その失敗が R1・R2 の批評そのものだという構造は、
  「数式だけで作った」を口で言うより遥かに伝わる。文字のコントラストと媒体の統一（全部チョークにする）だけで 9 まで届く。
- **定点を動かした件は、記録も理由も検証も正しかった。** ただし、その指摘を受けたラウンドで物差しを動かしたのは手続きとして良くない。
  旧 2 点を戻し、新 2 点を足すことを強く勧める（両方撮れるので、次ラウンドの比較が壊れずに済む）。
- **`?shot=storm` が `freeze=1` であるために、嵐の最大の破綻が定点撮影から構造的に漏れていた。**
  定点は「止めた 1 フレーム」だけでなく、「動かして数秒経った状態」も 1 つ持つべき。
- 合格条件（全定点 9・携帯 7・ブラインド全「される」）までの距離は縮んだが、上位 1・3（遠景の影と葉カード）が残る限り、
  どの定点も 7 を超えられない。次ラウンドはこの 2 つだけを直した画で再撮影するのが最短。
