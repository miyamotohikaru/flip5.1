## 批評側の自己訂正（嵐の空のマゼンタ）と、定点そのものの欠陥

**最初、私は「R5 のマゼンタの指摘は誤りだった」と書きかけた。それが誤りだった。**
`r6_storm`（`freeze=1`）だけを測ると空の R−G は +3 しかない。だが `freeze=0` で流して撮ると:

| フレーム | 空の R−G 中央値 | 95%点 | **G が 3 チャネルの最小の画素** | 空の明るさ(8bit) |
|---|---|---|---|---|
| `r6_storm`（定点・freeze=1） | +3.0 | +6.0 | 83.7% | 191.7 |
| `r6_storm_live`（8 秒後） | +4.0 | +14.0 | 80.4% | 182.0 |
| **`r6x_storm3`（3 秒後）** | **+27.0** | +34.0 | **95.7%** | 105.3 |
| `r6x_storm12`（12 秒後） | +2.0 | +22.0 | 52.6% | 175.3 |
| **`r6x_storm20`（20 秒後）** | **+27.0** | +34.0 | **92.5%** | 102.3 |
| **`r6x_storm30`（30 秒後）** | **+24.0** | +30.0 | **97.5%** | 98.3 |

**R5 の指摘は正しい。** 嵐の空は **R−G = +24〜+27、空の 93〜98% の画素で G が最小**の、
等倍で誰にでも分かるピンク〜藤色である（`r6x_storm30` を見れば一目で分かる。火星の砂嵐の色で、雷雨の色ではない）。
私が +3 を見たのは、**`storm` 定点も `storm_live`（8 秒）も、たまたま閃光で空が飛んでいるフレーム**だからである。

**ここから出る結論は 2 つある。**

1. **`storm` と `storm_live` の 2 定点は、いま嵐を代表していない。** 5 点サンプルのうち 2 点（8 秒・12 秒）が
   閃光フレームで、空の明るさが 98 → 192 と**倍近く跳ねる**。**採点対象の 2 枚が両方とも外れ値**という状態である。
   これは `weather/lightning` の発光間隔を 3〜4 秒 → 9〜18 秒にすれば自然に解消する（**R4 5 番から 3 ラウンド未着手**）。
   間隔を直すまでは、**定点は動かさない**（`docs/CRITIC.md` の教訓どおり）が、
   批評は毎回 `freeze=0` の 3/20/30 秒も必ず添えることにする。
2. **`storm` の点は R5 と同じ 4 のままにする。** 私は一度 5 を付けかけたが、その根拠（マゼンタは誤報）が消えた。
   良くなった点（稲光の枝分かれと光冠は本物）はあるが、**トーテムポールの木・輪郭だけの山・マゼンタの空**は 3 つとも残っている。

`docs/CRITIC.md` に足すべき教訓: **「動くものは freeze=1 では検証にならない」は、
悪いものを見落とすときだけでなく、良く見えてしまうときにも効く。** 今回は後者で危うく誤採点するところだった。

いっぽう `sunset_water` の「遠景の岸だけ夕日が当たっていない」は**本物のまま**:
岸の草 R/G = **0.974**、すぐ隣の日の当たる岩 R/G = **1.305**。R5（0.986 / 1.319）から動いていない。

## 担当が「この方法ではこれ以上は無理」と報告した項目

### ピンホール（`cloudy_side` 225 個）— 担当「殻を細くした代償。太らせると板に戻る」

**報告の因果は正しい。** そして**代案はある。** ピンホールは「隣り合うカードの間に、背景の空が
1〜2px だけ抜けて見える」現象なので、**カードを太らせずに、抜けた画素を空でなくする**方向で潰せる:

1. **アルファのしきい値を距離で動かす（最も安い）。** `alphaTest` を近景 0.5 → **遠景 0.25** に落とす。
   カードの形は変わらないが、縁の半透明部分が残るので 1px の穴がふさがる。
   3〜8m では今のままなので「板に戻る」は起きない。
2. **葉の背後に「暗い塗りつぶし面」を 1 枚だけ置く。** 半径を枝長の **0.10 倍**（いまの殻の 0.14 倍よりさらに細く）、
   `depthWrite=false`、色は葉の 0.45 倍。**輪郭を作らない大きさに留めれば「のっぺりした円錐」にはならない**。
   R6 で 0.32 → 0.14 に下げたのは正しい判断で、**0.10 まではまだ下げ代がある**。
3. **MSAA でなく、葉だけ alpha-to-coverage** にする。1px の穴は色が混ざって消える。
   `material.alphaToCoverage = true` の 1 行で、コストはほぼゼロ。
4. **どうしても残るなら「空でなく遠景の色」で埋める。** 穴から見えるのが空（輝度 0.85）だから点に見える。
   樹冠の描画時に `gl_FragDepth` を触らず、**葉の裏面（`side: DoubleSide`）を暗い色で描く**だけでも
   輝度差が 0.85 → 0.2 に落ちて「白い点」ではなくなる。

**したがって「現状で許容」とはしない。** 上の 1 と 3 は合わせて 2 行で、板に戻すリスクは無い。まずそれを試すこと。

### 影の帯が開けた場所にも掛かる（影担当が対応中）／地形の GPU 7.2ms

対応中と聞いているが、**採点には入れる**。今回の切り分けで**問題は「帯」だけではないことが分かった**ので、

### 1.（新・ただし R4 の「金床」から数えて 3 ラウンド）`flip_sunOcclusion` が世界全体を 0.85 段暗くしている — **core/lighting（影担当）**

今回いちばん大きい発見。切り分けは 3 枚で完結する:

| | 帯（林の足元） | その下の**開けた日なた**（木から 30m） |
|---|---|---|
| `?shot=noon_side&dbg=noveg` | 0.0933 | **0.1599** |
| `?shot=noon_side&dbg=noveg,noshadow` | 0.0933（**1 画素も変わらない**） | 0.1599 |
| `?shot=noon_side&dbg=noveg,nosunocc` | **0.1661**（+0.83 段） | **0.2877**（+0.85 段） |

つまり **CSM の落ち影は無関係で、`flip_sunOcclusion` が「木の下」だけでなく「開けた草地」まで
一律に 1.8 倍暗くしている**。R5 で「近景の地面が 3 段暗い」と書いた分のうち、
**地形担当が直したのは自分の持ち分だけで、残りの 0.85 段はここにある**。
さらに悪いことに、**帯の R/G は 0.966（灰色）／日なたは 0.829（緑）**で、
**遮蔽が草を脱色している**。本物の木陰は「緑のまま、空の青が乗って沈む」のであって、灰色にはならない。

直し方（3 つとも数値つき）:
1. **下限を入れる。** `occ = mix(1.0, rawOcc, k)` の形にして **`occ` の下限を 0.55**。
   いまは 0.30 前後まで落ちている（0.85 段 = 0.55 倍）。
2. **色を持たせる。** 遮蔽を輝度の掛け算でなく `directLight *= occ` ＋ `indirectLight *= mix(1.0, 0.75, 1-occ)` にし、
   **拡散の環境項（空の青）は落とさない**。目標は帯の R/G を 0.966 → **0.85〜0.88**（日なた 0.829 の少し上）。
3. **場を焼く。** 全画素で走らせるのをやめ、**64m/テクセルの低解像度テクスチャに焼いて bilinear で引く**。
   これで GPU 7.2ms が落ち、同時に**上端の硬い直線が消える**（いまの板の上端は 1px の直線）。
   仕上げに λ8m・振幅 ±2m のゆらぎを境界に足す。

**効く定点: `noon_side` `cloudy_side` `forest` `ridge` `noon`（5 枚）＋ GPU 時間。**

### 2.（**5 ラウンド連続 1 位**）インポスターの輪郭 — **vegetation/impostor**

`dbg=imponly` で確定している。いまインポスターは 3 種類の別の間違いをしている:

- **250m（`storm` (245,225)-(320,300)）**: 平らな四角い頂点＋その下に広い鍔＝**駒／ボラード**。
- **150m（`noon_side` (1370,165)-(1450,250)）**: 十字形のブロックの塊＋真ん中に幹色のひし形＝**緑のサボテン**。
- **1〜3km（`golden` y=290–490）**: 同じ濃さ・同じ大きさの縦の点が等間隔＝**胡椒の粒／ひげ**。

距離帯ごとに別々に直す:
1. **150〜400m**: アトラスのコマに **2px の透明マージン**を入れ、**膨張をコマ内でクランプ**する
   （いまは隣の段の幹色を拾っている＝ひし形の正体）。頂点は**上 15% を三角にテーパー**させ、
   **平らな上端を作らない**（`alphaTest` 前に上端 8px を線形にフェード）。
2. **400〜800m**: 個体を **2〜3 本まとめて 1 枚**の板に焼く（いまは 1 本 1 枚で、輪郭が全部同じ）。
   高さと横幅に ±35% のばらつき。
3. **800m 以遠**: 個体を描くのをやめ、**樹冠の被覆率**を地形のアルベドに焼き込む
   （λ40–80m のクラスタ、被覆 0〜0.85、色は葉の 0.7 倍）。1 本ずつ立てるのをやめれば胡椒は消える。

**効く定点: `storm` `storm_live` `cloudy_side` `golden` `noon` `cloudy` `sunset_water` `night` `ridge` ＋携帯 3 枚（12 枚）。**

### 3.（**4 ラウンド**）近景の草が「塗った地面に藁を刺した」画 — **vegetation/grass**

R4 の 3 番・R5 の 1 番と同じ指示。**1 本の草が 1 本のまっすぐな線**で、株にならず、
根元の接地の暗がりも無く、丈も向きも 1 種類しかない。
1. **1 株 = 3 枚**にして、葉を `y = 0.35·(x/L)²` の弧に曲げる。
2. **穂（種子頭）を 8% 混ぜる**。いま 100% が葉。
3. **密度を ×2.5**（`cloudy_side` は等倍で地面が透けている面積が 6 割）。
4. **株の根元に半径 3cm の接地の暗がり**（AO）。これが無いので「刺してある」ように見える。
5. **密度に λ8m の fbm（谷 40%）と踏み跡 1 本**（`dawn` の一様なカーペット対策）。

**効く定点: `golden` `dawn` `cloudy` `noon` `noon_side` `cloudy_side` `rain`（7 枚）。**

### 4.（**新規**）葉の付いていない裸の枝が樹冠の外に突き出す／頂芽がアンテナになる — **vegetation/conifer**

R6 でカードを 1/4 にした副作用。**いま 3〜8m の木で最も目立つ形の間違い。**
1. **カードを間引いた枝は、枝の円柱も一緒に消す。** あるいは枝の可視長を
   「その枝に残った最も外側のカードの根元」でクリップ。
2. **頂芽の裸の長さを樹高の 4% 以内**に。輪生の最上段を頂芽の根元まで上げる。
3. `r6_noon_side` (1370,170)→(1545,140) の**空を横切る 1px の点線**も頂芽まわりの縮退三角形に見える。同時に確認。

**効く定点: `forest` `ridge` `cloudy_side` `noon_side`（4 枚）。**

### 5.（**2 ラウンド**）葉カードがまだ「切った工作用紙」／サーモンの点 — **vegetation/conifer**

R6 で不透明になり一回り小さくなったのは本物の前進。だが等倍でまだ 1 枚ずつ数えられる。
1. **カードの最大寸法を樹冠半径の 0.22 倍以下**（いま 0.35 倍相当）、枚数を 2 倍。
2. **カード内に針の筋を入れる**。いま内側は 1 色で、輪郭のギザギザだけが針を表している。
   アトラスに λ2px の縦筋（コントラスト ±18%）を焼けば、平らさが消える。
3. **サーモンピンクの格子状の点**（`r6_ridge` (100,250)-(500,550) 3 倍）は**アトラス越しの滲み**。
   UV パディング 4px ＋ ミップの最上位 1 段を捨てる（`generateMipmaps` 後に `mipmaps.shift()`）。
4. **縁の 1px の階段**: `alphaToCoverage = true`（1 行、コストほぼゼロ、ピンホールにも効く）。

### 6.（**3 ラウンド**）雨に距離が無く、何にも当たらない — **weather/rain** ＋ **water** ＋ **terrain**

R4 の 5 番から動いていない。**雨天の 2 定点（`rain` `storm`）と `storm_live` が全部これで落ちている。**
1. **weather/rain**: alpha と長さを `1/(1+d/25m)`、40m 以遠は霧のベールに置換、本数 3 倍で近景だけ密に。
2. **water**: 湖面に法線リング（径 4mm、0.6m/s、40 個/m²/s）。いま**波紋が 1 つも無い**。
3. **terrain**: 雨天プリセットで roughness −0.25 / albedo ×0.75 の「濡れ」。いま**乾いた昼の地面に灰色を掛けただけ**。
4. **post/grade**: `rain` の彩度 0.150 → **0.22**、`storm` の非閃光フレームの R−G を +25 → **±4**。
5. **weather/lightning**: 発光間隔 3〜4 秒 → **9〜18 秒**。これで `storm` / `storm_live` の 2 定点が
   「たまたま閃光」でなくなる（上の自己訂正の節）。

### 7.（**2 ラウンド・× 判定**）岸の彗星形のにじみと、水際の縁石 — **terrain / terrain-glsl**

**削除した `rill` は犯人ではなかった**（`tSlope>0.17 && tDist<240 && tShore<25` で門番されており、
問題のにじみは 1.5km 先のほぼ平らな岸に出る）。切り分けをここまで進めてある:

- `dbg=noveg` で残る → **地形**。
- `tdbg=8`（地色だけ）で**一貫度が 0.580 → 0.672 に上がる** → **アルベドの層**にある（照明ではない）。
- `tdbg=9`（細部なし）で無変化 → **「細部」の層ではない**。
- カメラを 20° 回すと縞の向きが 174.2° → 10.7° に回る → **世界に固定**（画面固定の異方性フィルタ不足ではない）。
- 縞は**ただ 1 つの世界方向**に揃っている。

したがって疑うべきは `glsl.ts` の**「1 つの世界方向へ引き伸ばした異方性ノイズ」の一族**である:
`vec2 sa = vec2(dot(tXZ, tWind), dot(tXZ, perp))` ＋ `f0 = vec2(0.018, 0.055)`（**3:1 に引き伸ばし**、~L283）、
`vec2 xa = vec2(dot(tXZ, wdir), dot(tXZ, perp))`（~L338）、
`dot(tXZ, vec2(0.92, 0.39))`（~L412）、`dot(tXZ, vec2(0.36, -0.93))`（~L395）。
**この 4 か所を 1 つずつ 0 にして撮れば 1 ラウンドで確定する。** 見つけたら
① 向きを場所ごとに振る（λ200m の回転場 ±60°）、② 引き伸ばし比を 3:1 → 1.6:1、③ 振幅を 1/3。

併せて **水際の縁石**（`noon` x=200–1400 / y=440–740 の幅 8〜15px の均一な灰紫）を、
「濡れ砂（暗く彩度低め）→ 乾き砂 → 草」の 3 段に分け、幅に λ6m のゆらぎ ±40% を入れる。

### 8.（**5 ラウンド**）裏返し側が 5 ラウンド動いていない — **vegetation（裏返し分岐）** ＋ **terrain** ＋ **ui/labels**

3. **ふだが UI の箱**: チョーク／線画の枠に。**`Blackboard.tsx` の線文字は実装済みで流用できる**。
   入口の黒板と裏返しのふだが同じ媒体になれば、「入口で説明したことが、世界の中で起きている」がつながる。
4. **木を骨組みに**: 幹 1 本＋輪生 5 段の線（各 8 本）。いまは小さな三角の粒。

### 9.（**4 ラウンド・1 行で直る**）蛍が湖面の上に浮く／湖面の横縞 — **weather** ＋ **water**

`r6_night` の (530,630) (600,628) (765,660) (935,700) (1150,645) の 5 個。
**R3 の 8 番から 4 ラウンド、同じ 1 行の指示が実行されていない**: 蛍を `vDepthA > 0` で 0。

### 10.（**3〜4 ラウンド**）遠景の「情報ゼロ」を 3 か所で埋める — **terrain/glsl** ＋ **sky**

R6 で中景の低い側（λ36/13/6m）は入った（高周波 +34〜69%）。**残りは 3 つ**:
1. **λ1.5m の段が無い**。`midN` のブロックに `tn_gnoised(tXZ * 0.66)` を振幅 0.20 で足す
   （近景の `dirt` で使っているのと同じ）。いま 100m 先が「ぼかした写真」に見えるのはこれが理由。
2. **`midN` の始点が遠すぎる**。`smoothstep(25.0, 70.0, tDist)` → **`smoothstep(12.0, 40.0, tDist)`**。
   `ridge` の 30〜120m の斜面が中景ノイズの外側に落ちていて、ぼかした泥のままになっている。
3. **空気遠近に下限が無い**。`storm` の 3km の山は Y=0.5410、すぐ上の空は 0.5387 で**差 0.4%**。
   **sky**: `mix(sceneCol, hazeCol, t)` の `t` を **0.98 で頭打ち**にし、最遠でも 0.02 の差を残す。
   併せて `sunset_water` の遠景の岸に**太陽の色温度を掛ける**（岸 R/G 0.974 → 目標 1.10 前後。
